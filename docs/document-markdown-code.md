# Document Markdown code ownership

The marked document export path normalizes only the regenerated Lexical code
shape to native Pandoc `PRE/CODE`: known code-module class, optional validated
language/highlight metadata, spellcheck default, stable document identity and
text/default pre-wrap spans/line breaks. Line breaks become newlines; code owns
its exact whitespace. The known class pattern is grounded in companion 95's
`DocumentEditor-module__qFNIka__code`, not arbitrary authored code classes.

Unknown rich PRE presentation remains one complete HTML RawBlock owner. Inline
CODE remains a complete HTML RawInline owner, preserving its wrapper, attributes
and exact exported source text. Existing styled spans retain their outermost
source owner; nested CODE does not create a competing descendant owner. The
native Pandoc JSON bridge restores Div/Span sentinels and refuses missing,
duplicated or conflicting owner identities. It does not hand-render Markdown or
modify the conditional source document.

## Evidence and limits

The fixture was generated by actual pinned `@lexical/code` 0.36.2 and
`@lexical/html` exports, including the theme class, spellcheck/language metadata,
default TextNode wrappers and BR. A real Lexical regression regenerates its exact
shape. The prior source's contained renderer-40 Pandoc conversion failed the
same fixture's native CodeBlock/language/text oracle: it returned styled raw
span text instead of fenced code. This is the observed defect, rather than a
hypothetical missing-owner refusal.

The new source passed actual network-disabled, read-only renderer-40 Pandoc
conversion: native fenced JavaScript retained exact two-line indentation and
language through GFM JSON readback; unknown rich PRE retained class/style/text
through GFM-to-HTML readback; outer styled SPAN containing CODE exported as one
source owner without generated-ID leakage. Whole inline CODE appeared verbatim
in exported Markdown.

**Still open:** Pandoc's GFM-to-HTML import collapses repeated spaces inside the
raw inline CODE content, even though export preserves the raw source exactly.
The actual readback changed ` x  y ` to ` x y ` while retaining the CODE wrapper
and attributes. This slice does not claim exact inline-code import roundtrips,
new-build browser qualification, publication, or complete document fidelity.

Author checks passed 16 daemon normalization/owner cases and six web HTML cases,
including real Lexical fixture regeneration. Daemon source/test TypeScript,
web TypeScript and the repository guard passed. These are source/contained
converter checks; the next immutable companion/renderer browser export check
remains a separate gate.

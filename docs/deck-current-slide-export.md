# Current-slide PNG export

Runtime 113 selected slide 2 of an owned two-slide fixture but its PNG job omitted `index` and downloaded the first red slide. A normal API control for the same unchanged source with `index: 1` downloaded the second blue slide. This is a source-selection plumbing defect, not a missing renderer index option. No reference artifact was exported.

The next source checkpoint binds image intent to original file bytes, a canonical source path and a zero-based source ordinal. Its conversion-only capture records the original parser-created slide object before authored DOM replacement. Runtime movement can retain that object; copied markers do not establish identity. Original-byte SHA is checked before any conversion. Existing explicit-index callers without the new binding remain compatible. PDF/PPTX behavior is unchanged.

Initial first-child-stub-only acquisition failed an actual Chromium ancestor-MutationObserver replacement case: the parser attached the stub to a connected clone. The corrected init capture also retains parser `addedNodes` identity through its first-installed observer and pristine `takeRecords`, then requires the stub's parent to be that same object. In an existing network-disabled renderer56 container, source-helper overlay tests passed moving the original, refusing duplicate markers, refusing one clone after removing the original, and refusing immediate ancestor-observer replacement. This is source-helper proof, not a new immutable worker or UI pair. Native source-byte/selection wiring and packaged acceptance are still pending.

The follow-up byte/host bridge checkpoint obtains SHA-256 from the full source response's `arrayBuffer` before decoding. Its optional proof uses the same fatal UTF-8 decoder in preview and worker, strips a leading UTF-8 BOM only from the decoded projection, and retains the digest of the original BOM/non-ASCII bytes. Invalid UTF-8 leaves legacy text display available but cannot create new source-bound PNG intent. Cached source stores this optional byte proof under the existing exact authorization/file/refresh identity; unsaved or unproved source does not acquire a digest by re-encoding text.

The existing presentation controller publishes a separate strict export selection. It uses the generation-checked source path mapped to the saved source ordinal, rather than the current runtime ordinal. Dirty/saving, inactive, unsupported root/count and source/transport mismatch withdraw intent. This is implementation and focused source-test evidence only; a new packaged native/companion pair still needs actual export/readback and lifetime qualification.

# Clean History pause and native history continuity

A whole-file History restore closes the current Writer while preserving the visible SDK kernel. Previously, a rejected restore could create a replacement Writer while the existing membership controller still referenced the closed one. Rebinding every replacement would be unsafe: a recovered checkpoint or an external source replacement cannot recreate privately issued native history.

This source checkpoint captures one live, single-use handoff before closing a clean Writer. The ticket stays in private closures, never draft JSON. It binds the exact journal and scope, qualified source, complete protected checkpoint, current native registration/focused-history checkpoint and entry IDs, actual SDK snapshot, and calculation input epoch. A new Writer may consume it only after the same restore operation has a checked terminal conflict/cancelled/unadmitted outcome, a fresh authorized unchanged source SHA, successful protected-intent clearance, and safe restore-lease release. The actual hook-issued lease identity is required; copying its fields does not issue another lease.

The captured checkpoint is restored before the old controller receives the new Writer. The controller, native entries and calculation worker remain the same. Formula cache value/type may differ only on cells retaining their exact formula; formula identity, shared owner, rich text, styles, geometry, sheet membership/order/names, custom metadata and view data remain exact. The calculation owner must prove the same input epoch and actual quiescence. Only new Writer desired presentation receives such legitimate cache updates; source model, acknowledged snapshot, checked ACK/binding and protected pools keep their original authority.

Authored sheet mutations are frozen before waiting for calculation. Exact provenance/vector-matched cache applications can finish, but a fromFormula flag alone cannot admit a value. Same-workbook async and sync Undo/Redo are refused before native dispatch during the pause; unrelated Doc history remains delegated. Failed capture can release the gate only back to the exact still-live qualified owner. Worker failure or lost ownership cannot unfreeze it through a finally callback.

An uncertain restore retains the exact closed source/checkpoint/ticket for status-only reconciliation. A later no-effect status retry can deliver its evidence even though that retry did not pause again. Wrong operation, changed source/model or withdrawn journal cannot hand back. Ordinary Writer replacement instead requests the existing kernel-reset boundary exactly once; it cannot revive old issuers or silently attach the old controller to an arbitrary Writer. This observation does not restart a failed worker merely because its lease became null.

## Source proof

The live hook tests use the actual pinned SDK, real calculation RPC worker, scoped controller and existing Writer/journal path. Their save receipts/previews are deterministic stand-ins: they do not establish HTTP, historical-asset or filesystem lineage. They cover a privately issued Add/save followed by verified resume and protected Undo/save; uncertain and wrong-operation retry; revoked journal and same-SHA model replacement; ordinary replacement reset; and an ordinary Save held behind its real reverse cache application. The normalizer/cache-application integrity tests are recorded separately in [the application barrier record](workbook-calculation-application-barrier.md).

A separate real worker test imports formula cache 999 for deterministic inputs 21+17. After pause capture, an epoch-stamped host calculation applies 38. Handback retains the native entry ID, updates desired cache to 38, and leaves source/acknowledged/ACK/binding data exact. That test deliberately seeds an ordinary entry through the public SDK history API to isolate late initial calculation; it is not membership issuance or serialized history restoration. The Add/save matrix supplies the independent private-birth continuity proof.

The ordinary Redo boundary test initially expected rejection, while the old base handler actually returned false after the frozen mutation was refused. That was not evidence of a lost stack entry: the pinned base handler moves history only after successful sequence execution. The new explicit pre-dispatch pause is tested with complete snapshot/checkpoint invariants, and unrelated Doc delegation remains covered.

The Node facade executeCalculation experiment failed closed because its generic trigger service also scheduled an unstamped worker-local start. The late-cache proof uses the actual supported epoch-stamped host Start path. Browser/facade parity remains unqualified; no worker epoch exception was added.

## Remaining gates

Controls remain hidden. This checkpoint is local source/SDK/RPC proof, not a packaged browser, server-history asset, release or production qualification. It also precedes refresh onto the newer reviewed source-producer and maintenance ancestry. That follow-up must forward the complete guarded journal provider, drain maintenance before capture, install/start/stop maintenance in the real Grid lifetime, and mark checked ACK/rebind transitions before combined browser qualification. Reload still starts new native history; recovered JSON is retained data, never a source of live native issuance.

Final source checks: 103 affected cases passed across seven files with `--maxWorkers=1`; full workspace and web typechecks and guard passed. The preceding parallel run had 100 passes and three unchanged 5-second Worker readiness failures. All three failed scenarios then passed serially before the complete serial run. Those failures and CPU/memory pressure observations were retained; contention is a supported hypothesis, not a proven cause or a label of flaky tests. No startup limit, execution deadline or assertion was relaxed.

# Presentation entry keyboard focus

On the owned 136/79 preview, native `45e7b550` and fork `9e35cf7e`, normal Present opened a correctly painted Third GREEN slide but left both the host and the companion document's active element at BODY. Trusted ArrowLeft did not change the visible slide. The hidden chat textarea was not focused and retained its exact unsent draft. This was observed with the actual GUI on the recorded disposable `deck.html` fixture, not inferred from a component test.

An actual stage click moved focus through the outer iframe to the sandboxed `present` iframe. It also navigated the deck, so clicking is not an acceptable keyboard-entry workaround. After focus entered the stage, trusted arrow navigation changed the painted slide and Escape closed presentation and browser fullscreen. The separate speaker-notes window already handled Left/Right. These are distinct paths.

The source correction focuses the current connected presentation iframe on its first load, using native iframe focus with `preventScroll`. Both srcdoc and URL presentation transports share the handoff. The active workspace, current overlay and exact element must still own the load. A source/file key replaces the iframe across ownership changes; repeated loads do not reclaim focus from the exit control. No new key forwarding, sandbox DOM access, source mutation, calculation authority or navigation transport is introduced. Existing exit focus behavior and chat ownership are retained.
